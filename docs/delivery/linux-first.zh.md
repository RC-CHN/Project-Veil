## OpenWrt 边界

- veild 保持前台进程，配置、退出和诊断语义由共用 node 提供。systemd/procd 各自管理服务，不进入 core。
- DNS、路由、防火墙通过领域接口与适配层接入，首轮不强制依赖 systemd-resolved。OpenWrt 的 netifd、firewall4 和现有 DNS 服务需要独立集成与验收。
- 主机本地出站和 LAN 转发是两种接入范围。后者不能只按本机进程 UID 判断，不把当前工作站规则直接宣传为路由器支持。
- 配置目录、状态目录、运行身份和网卡名由安装/平台层确定；不在协议库写死 UID1000、systemd 路径或固定网卡名。
- 节点运行不要求 Python、Docker 或桌面环境。当前 Python 工具是开发/验收入口，不是节点运行依赖。
- 将来为路由器单独确认架构、内核功能、内存、日志与闪存写入预算。Linux/amd64 或 Windows 交叉构建通过不等于 OpenWrt 支持。

## 本轮之后仍需完成

第一批的回环进程验证不能代替真实公网签发和 VPS 连通性；尚无指定受控 VPS 执行环境。下一批优先做 Linux 安装及服务，随后 TUN/DNS 组合验证；事件归档、私有持久事务和证书恢复按依赖逐步接入。GUI、Windows 原生验收和性能优化不作为当前 Linux 实战链路的前置工作。
